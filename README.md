# Android Static Analysis Skill

[中文](README.zh-CN.md)

> **Zero-dependency Android privacy & telemetry static analysis Skill for AI Agents** — inspect permissions, SDKs, network endpoints, and bounded source-to-sink dataflows using only the Python 3.10+ standard library.

## Features

- **Zero-Dependency & Sandbox-Ready**: Pure Python 3.10+ standard library engine with no JVM, build steps, or third-party packages required.
- **Full APK & Device Snapshot Analysis**: Inspects single or split APKs directly and collects read-only package metadata and APK snapshots from authorized ADB devices.
- **Bounded Privacy Dataflow & Strict Evidence Levels**: Separates E0–E2 static declarations/clues from E3/E4 modeled source-to-sink paths while keeping unknown calls and budget limits explicit as coverage gaps—never claiming observed runtime uploads.
- **Context-Friendly & Redacted by Default**: Produces lightweight summaries and paginated SQLite queries (`has_more` / `next_offset`) with automatic masking for URL credentials and query parameters.
- **Durable Batch Storage & Resource Guards**: Checkpoints facts in SQLite v4, supports cross-directory `--resume`, and enforces a hard preflight free-disk reserve (`estimated peak + max(4 GiB, 20%)`) alongside cooperative memory and scheduling budgets.
- **Structured AI Assessment & User Advice**: Registers every target in `assessment.json`, validates evidence references and prerequisites, and renders actionable recommendations in `user-advice.md`.

## Quickstart

**Prerequisites**: `Python >= 3.10` (standard library only). Optional: `adb` for physical device snapshot collection; `jadx` for supplemental decompiled text scanning.

### Method 1: Remote / Zero-Install (Recommended)

Send the following prompt and link to an AI Agent with command execution and web access:

> Read and follow this Skill, prepare the project in my current workspace, then analyze the APK or authorized device I provide. Read the complete instructions before proceeding:
>
> https://github.com/Mgrsc/apklens-skill/blob/main/online-static-analysis/SKILL.md

The AI will fetch the project via [online-static-analysis/SKILL.md](online-static-analysis/SKILL.md), record the verified commit, and hand off execution to the main Skill ([raw Markdown](https://raw.githubusercontent.com/Mgrsc/apklens-skill/main/online-static-analysis/SKILL.md) fallback).

### Method 2: Local Workspace

If you have cloned this repository locally, instruct your AI assistant:

> Read [SKILL.md](SKILL.md) in this project root and follow its guidelines to analyze the APK or authorized device I provide.

- **Direct CLI Execution (Optional)**: Run the deterministic analyzer directly without an AI:
  ```sh
  python3 scripts/analyze.py scan --apk path/to/app.apk --output output_dir
  ```
- **Physical Device Analysis**: Enable USB or wireless debugging so `adb devices -l` shows state `device`. The AI will guide you through pairing and read-only snapshot collection.

## Output Artifacts

Standard engine outputs written to the task directory:

- `report.md`: Deterministic Markdown audit report with facts and review prompts.
- `summary.json`: Lightweight summary (`summary.facts` and Top 20 priority list) optimized for AI context consumption.
- `analysis.sqlite3`: Authoritative SQLite database with checkpoints and indexed facts; preferred input for `scripts/query_results.py` on large tasks.
- `analysis.json`: Compatible machine-readable full export (optional via `--skip-analysis-json`).
- `snapshot.json` / `progress.json` / `performance.json`: Reusable device collection snapshot, execution milestone, and phase timings/resource peaks.
- `domains.txt` / `telemetry-domains.txt`: Retained network endpoint candidates and telemetry-tagged domain candidates (not drop-in blocklists).

AI assessment outputs written to a separate directory via `scripts/assess_results.py`:

- `assessment.json`: Full application register tracking evidence reviews, deferrals, action prerequisites and an optional source-bound reporting plan for issue groups and routine records.
- `delivery-summary.json`: Deterministic analysis/review states, stop reason, recorded claim/recommendation counts and separate report-planning status; use this for final completion statements. Generated by preparation and rendering, and returned by validation as `delivery_summary`.
- `user-advice.md`: Concise human-facing conclusions, priorities and selected issue cards. Reviewed applications are not automatically expanded; full registration, evidence references and statistics remain in the linked ledger and delivery summary.
- `report-details.md`: Optional issue/member details for larger groups and issues outside the main page. Conditions and material differences remain explicit; historical ledgers without a reporting plan get clearly identified uncurated details rather than guessed priorities.

Component candidates, unclassified vendor references and address references are reported separately. Foundation libraries do not imply advertising or analytics, and domain-only matches do not establish SDK integration. Known documentation/policy/schema references stay in the inventory while telemetry candidate views exclude them. E2 records retain instruction evidence; snapshot-only grants do not become Manifest declarations. See [Evidence and Coverage](references/evidence-and-coverage.md) for the versioned semantics and legacy unknowns.
